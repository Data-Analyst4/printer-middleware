# Remote Deployment Checklist

This checklist turns the local printer middleware into a Windows machine service
that:

- starts automatically when Windows boots
- restarts automatically if the middleware process crashes
- stays reachable over the internet through a named Cloudflare Tunnel
- can be called by a web app using the `/print` API endpoint

Why a Windows service and not Task Scheduler or Startup folder:

- this project is a web API, not a desktop tray app
- it should start before any user logs in
- it should keep running headless in the background
- it should restart automatically if the Python process exits

The older `middleware-app` pattern that uses Task Scheduler, VBS, and the
Startup folder is useful for interactive GUI apps. For this project, the
preferred and more reliable pattern is `NSSM + Windows Service`.

## 1. Prepare the PC

- Make sure Windows can boot normally after power loss if that matters for your site.
- In BIOS/UEFI, enable the equivalent of `Restore on AC Power Loss` or `Power On After Power Failure` if you want it to come back after electricity returns.
- If you want to wake the PC remotely from a fully powered-off state, configure `Wake-on-LAN` in BIOS and Windows. This is separate from the middleware.

## 2. Prepare the project

Open PowerShell in:

```powershell
cd C:\Users\DELL\printer-middleware
```

Create and populate the virtual environment if needed:

```powershell
python -m venv .venv
.\.venv\Scripts\activate
pip install -r requirements.txt
```

Quick local test:

```powershell
.\.venv\Scripts\python.exe main.py
```

From a second terminal:

```powershell
Invoke-RestMethod -Method Get -Uri http://127.0.0.1:5000/health
```

Expected result:

```json
{"status":"healthy","service":"printer-middleware"}
```

Stop the manual server before installing services.

## 3. Install NSSM for the middleware service

`NSSM` is used so the middleware:

- starts on boot
- restarts automatically on crash
- can run without you manually opening a terminal

Install NSSM:

```powershell
choco install nssm
```

Confirm it is available:

```powershell
nssm version
```

## 4. Install the middleware as a Windows service

Run an elevated PowerShell or Command Prompt as Administrator.

Then run:

```powershell
cd C:\Users\DELL\printer-middleware
.\install_middleware_service.bat
```

If port `5000` is already used by something else, install on another port:

```powershell
.\install_middleware_service.bat 5001
```

This script:

- installs service name `PrinterMiddleware`
- runs `main.py --host 0.0.0.0 --port <port>`
- sets auto start
- configures restart on crash
- configures Windows Service recovery restart rules
- writes service stdout/stderr to:
  - `logs\service-output.log`
  - `logs\service-error.log`

Useful commands:

```powershell
sc query PrinterMiddleware
sc start PrinterMiddleware
sc stop PrinterMiddleware
.\uninstall_middleware_service.bat
nssm edit PrinterMiddleware
```

## 5. Test the middleware service locally

Confirm the service is listening:

```powershell
netstat -ano | Select-String ':5000'
```

Test the API:

```powershell
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:5000/print -ContentType 'application/json' -Body '{"printer_id":"P1","printer":{"ip":"192.168.29.110","port":2030},"command":{"command":"STAR","templatename":"DEMO","startpage":"1","endpage":"1","loop":"true"}}' | ConvertTo-Json -Depth 10
```

Check logs if needed:

```powershell
Get-Content .\logs\app.log -Tail 50
Get-Content .\logs\app.jsonl -Tail 20
```

## 6. Install cloudflared

Install Cloudflare Tunnel:

```powershell
choco install cloudflared
```

Confirm it:

```powershell
cloudflared --version
```

## 7. Create a named tunnel

In PowerShell:

```powershell
cloudflared tunnel login
cloudflared tunnel create printer-middleware
```

The second command creates a tunnel credentials JSON file in:

```text
C:\Users\DELL\.cloudflared\
```

## 8. Create DNS routing for the named tunnel

Pick a hostname such as:

```text
print.yourdomain.com
```

Route the hostname:

```powershell
cloudflared tunnel route dns printer-middleware print.yourdomain.com
```

## 9. Create the cloudflared config file

Copy the example file from the repo:

```powershell
Copy-Item .\config\cloudflared\config.yml.example $HOME\.cloudflared\config.yml
```

Edit:

```text
C:\Users\DELL\.cloudflared\config.yml
```

Replace all placeholders:

- `tunnel:` -> your real tunnel UUID
- `credentials-file:` -> the real JSON file generated by `cloudflared tunnel create`
- `hostname:` -> your real hostname such as `print.yourdomain.com`

Make sure this line stays:

```yaml
service: http://127.0.0.1:5000
```

That means Cloudflare will forward internet traffic to the local middleware service.

## 10. Test the named tunnel manually once

Before installing it as a service, do one manual validation:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run_tunnel.ps1
```

If that passes, your tunnel config is valid.

## 12. Lock down CORS before production

The install script currently sets:

```text
CORS_ORIGINS=*
```

That is okay for testing, but for production you should restrict it to your real frontend domain.

Example:

```text
https://app.yourdomain.com
```

Update the environment for the middleware service with:

```powershell
nssm set PrinterMiddleware AppEnvironmentExtra "HOST=0.0.0.0" "PORT=5000" "CORS_ORIGINS=https://app.yourdomain.com" "PRINTER_READ_TIMEOUT=5" "PRINTER_FIRE_AND_FORGET=false"
sc stop PrinterMiddleware
sc start PrinterMiddleware
```

## 15. What this setup gives you

- The Windows PC hosts the printer middleware locally
- The middleware starts automatically at Windows boot
- The middleware restarts if the process crashes
- `cloudflared` starts automatically too
- A web app can send JSON commands over the internet through your Cloudflare hostname

## 16. Important limitations

- If the PC is fully shut down, the API is unavailable until the PC powers back on.
- If you need remote power-on, configure `Wake-on-LAN`.
- If power is lost, automatic recovery depends on BIOS/UEFI power settings and Windows auto-start.

## 17. Troubleshooting

### Old queue-based API response still appears

- Stop all old Python processes listening on port `5000`
- Confirm only the `PrinterMiddleware` service is serving `5000`
- If another app already owns `5000`, reinstall this middleware on a different port
  and update your Cloudflare config to point to that port instead

```powershell
netstat -ano | Select-String ':5000'
```

### Tunnel works but web app gets blocked in browser

- Check `CORS_ORIGINS`
- Use your exact frontend origin, not `*`, in production

### Tunnel gives 502

- Confirm middleware is alive locally:

```powershell
Invoke-RestMethod http://127.0.0.1:5000/health
```

- Confirm cloudflared config points to:

```text
http://127.0.0.1:5000
```

- If you installed the middleware service on a different port such as `5001`,
  make sure the Cloudflare tunnel config uses that exact port

### Printer commands timeout

- Review:
  - `logs\app.log`
  - `logs\app.jsonl`
- Increase read timeout if needed
- Confirm the printer actually replies for that command flow
